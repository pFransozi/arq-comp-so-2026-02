Aula 07 · representação de dados

Como o computador representa números

Na aula anterior acompanhamos onde os dados ficam e quanto custa acessá-los. Agora vamos olhar para dentro desses dados. Fisicamente, o hardware utiliza estados físicos distintos; a arquitetura digital os abstrai como bits 0 e 1. O padrão de bits, sozinho, não informa todo o significado. A mesma sequência pode representar um número, um caractere, parte de uma instrução, uma cor ou outro tipo de dado. Nesta aula, quando fizermos conversões numéricas, assumiremos inteiros não negativos.

1 · Sistemas posicionais

Antes do binário: por que a posição importa?

Comece pelo sistema que já usamos todos os dias. Em 538, os algarismos 5, 3 e 8 não valem apenas cinco, três e oito: cada um é multiplicado pelo peso da posição em que aparece.

53810 = 8 × 1 + 3 × 10 + 5 × 100 = 538
DígitoPosiçãoPesoContribuição
8unidades10⁰ = 18 × 1 = 8
3dezenas10¹ = 103 × 10 = 30
5centenas10² = 1005 × 100 = 500

É por isso que o sistema é chamado de posicional: o valor de um dígito depende do próprio dígito e da posição que ele ocupa.

O que significa a base?

A base informa quantos símbolos diferentes podem ser usados em cada posição. Ela também define os pesos das posições, contados da direita para a esquerda: base⁰, base¹, base², base³...

Base 10Decimal

Leia da direita para a esquerda:
1000 = 10³ ← 100 = 10² ← 10 = 10¹ ← 1 = 10⁰

Base 2Binário

Leia da direita para a esquerda:
16 = 2⁴ ← 8 = 2³ ← 4 = 2² ← 2 = 2¹ ← 1 = 2⁰

Base 16Hexadecimal

Leia da direita para a esquerda:
4096 = 16³ ← 256 = 16² ← 16 = 16¹ ← 1 = 16⁰

Regra para ler qualquer sistema posicional: comece pela posição mais à direita, cujo peso é base⁰ = 1, e avance para a esquerda: base¹, base², base³...

A mesma regra no binário

No número 1011₂, começamos pelo bit mais à direita. Como a base é 2, os pesos crescem assim: 1, 2, 4 e 8.

BitPotênciaPesoContribuição
12⁰11 × 1 = 1
12¹21 × 2 = 2
02²40 × 4 = 0
12³81 × 8 = 8
10112 = 1 + 2 + 0 + 8 = 1110

A base muda a escrita, não o valor

Exemplo

4210 = 1010102 = 2A16

As três notações representam a mesma quantidade.

Como saber qual base está sendo usada?

Nesta aula

Usaremos um índice para indicar a base: 1011₂, 42₁₀ e 2A₁₆. Em programação, também são comuns prefixos como 0b para binário e 0x para hexadecimal.

Próximo passo: no computador, a base 2 é especialmente importante porque cada posição pode assumir apenas dois estados. Agora vamos ver o que acontece quando combinamos vários bits.

2 · Bits, bytes e capacidade

De um bit a muitos padrões

No modelo digital, um bit pode assumir dois valores lógicos: 0 ou 1. Esses valores abstraem estados físicos do hardware. Quando adicionamos outro bit, cada padrão existente pode terminar em 0 ou em 1. Por isso, a quantidade de combinações dobra a cada novo bit.

Quantidade de bitsPadrões possíveisExemplos
1 bit2¹ = 20, 1
2 bits2² = 400, 01, 10, 11
3 bits2³ = 8000 até 111
4 bits2⁴ = 160000 até 1111
n bits → 2n padrões possíveis

Observe o crescimento: 1 bit gera 2 padrões; 2 bits geram 4; 3 bits geram 8; 4 bits geram 16. Cada novo bit dobra a quantidade de padrões disponíveis.

O que acontece com 8 bits?

Com 8 bits temos 2⁸ = 256 padrões diferentes. Esses padrões vão de 00000000 até 11111111.

00000000primeiro padrão0
00000001próximo padrão1
11111110penúltimo padrão254
11111111último padrão255
256 padrões não significa que o último valor seja 256. Como a contagem começa em 0, os 256 padrões correspondem aos valores de 0 a 255.
1 posição bináriaBit

É a menor unidade usada aqui para representar informação. Pode assumir 0 ou 1.

8 bitsByte

Um byte reúne 8 bits. Portanto, possui 2⁸ = 256 padrões possíveis.

Depende da arquiteturaPalavra

É uma quantidade de bits tratada como uma unidade natural pela arquitetura ou pelo processador. Seu tamanho depende da máquina e não precisa ser igual a um byte.

Mais bits, mais possibilidades

LarguraPadrões possíveisContagem a partir de 0
4 bits2⁴ = 160 a 15
8 bits2⁸ = 2560 a 255

3 · Decimal e binário

Escrever a mesma quantidade em outra base

Converter não muda o número. Muda apenas a forma de escrevê-lo. Vamos fazer os dois caminhos separadamente: primeiro binário → decimal e depois decimal → binário.

Binário → decimal: descubra quanto cada bit vale

Use a mesma regra dos sistemas posicionais: comece pelo bit mais à direita. Ele tem peso 2⁰ = 1. A cada posição para a esquerda, o peso dobra.

101101₂
Passo 1Comece pela direita e associe os pesos: 1, 2, 4, 8, 16, 32.
Passo 2Multiplique cada bit pelo peso da posição.
Passo 3Some as contribuições.
BitPotênciaPesoContribuição
12⁵321 × 32 = 32
02⁴160 × 16 = 0
12³81 × 8 = 8
12²41 × 4 = 4
02¹20 × 2 = 0
12⁰11 × 1 = 1
1011012 = 32 + 0 + 8 + 4 + 0 + 1 = 4510
Atalho mental: posições com bit 0 não acrescentam valor. Nesse exemplo, basta somar os pesos das posições que têm bit 1: 32 + 8 + 4 + 1 = 45.

4 · Hexadecimal

Quatro bits de cada vez

O binário é adequado ao hardware, mas sequências longas de 0 e 1 são difíceis de ler. O hexadecimal é uma forma mais compacta de escrever os mesmos padrões. Como 16 = 2⁴, cada dígito hexadecimal representa exatamente 4 bits.

Ideia principal: hexadecimal não cria novos dados e não altera os bits. Ele apenas oferece uma escrita mais curta para padrões binários. Um grupo de 4 bits também é chamado de nibble.

Por que aparecem as letras A, B, C, D, E e F?

Na base 10 temos dez símbolos, de 0 a 9. Na base 16 precisamos de dezesseis símbolos. Depois do 9, usamos as letras A até F para representar os valores de 10 a 15.

Observe: 1111₂ é o maior padrão possível com 4 bits. Em decimal ele vale 15 e, em hexadecimal, é escrito como F₁₆.

Binário → hexadecimal: agrupe de 4 em 4

Para converter binário em hexadecimal, não precisamos passar primeiro pelo decimal. Basta separar os bits em grupos de 4, começando pela direita.

101010₂
Passo 1 · AgrupeDa direita para a esquerda: 10 1010.
Passo 2 · CompleteO grupo da esquerda tem só 2 bits. Complete com zeros: 0010 1010.
Passo 3 · Converta cada grupo0010 = 2 e 1010 = A.
1010102 → 0010 1010 → 2 A → 2A16
Regra: complete com zeros apenas à esquerda do primeiro grupo, quando necessário. Adicionar zeros à esquerda não altera o valor representado.

Hexadecimal → binário: faça o caminho inverso

Agora cada dígito hexadecimal é substituído diretamente pelo seu grupo de 4 bits.

3F₁₆
Primeiro dígito3 = 0011.
Segundo dígitoF = 1111.
Junte os grupos3F₁₆ = 00111111₂.
3F16 → 0011 1111 → 001111112
4 bits1 dígito hexadecimal

Um grupo de 4 bits pode assumir 16 padrões, de 0000 a 1111: exatamente os símbolos 0 a F.

8 bits2 dígitos hexadecimais

Um byte pode ser escrito com dois dígitos hexadecimais: de 00 até FF.

Uso práticoMais fácil de inspecionar

Hexadecimal aparece em bytes, endereços de memória, dumps, opcodes e documentação de baixo nível porque reduz sequências longas de bits.

Ideia central: hexadecimal funciona como uma abreviação do binário. Cada dígito hexadecimal corresponde a 4 bits; por isso, a conversão entre as duas bases pode ser feita diretamente por agrupamento.
