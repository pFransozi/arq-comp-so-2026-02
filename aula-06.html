1 · Hierarquia

Nem todo acesso aos dados tem o mesmo custo

Durante a execução, a aplicação depende de dados que podem estar em diferentes níveis de armazenamento. Quanto mais próximo o dado estiver do processador, menor tende a ser o tempo de acesso. Em compensação, a capacidade disponível costuma ser menor.

01

Registradores

São pequenos espaços de armazenamento dentro do processador, usados para manter valores diretamente envolvidos na execução das instruções.

Papel na execuçãoMantêm operandos e resultados temporários próximos das unidades de execução, reduzindo a necessidade de buscar cada valor na memória.
Relação com o softwareO compilador procura manter operandos em registradores pelo maior número possível de operações e recorre a operações de carga e armazenamento quando isso não é possível.
02

Cache

É uma memória menor e mais rápida que a memória principal, usada para aproximar da CPU dados e instruções com alta probabilidade de reutilização.

Papel na hierarquiaOrganiza a movimentação entre memória principal e registradores para reduzir o tempo médio de acesso.
Níveis de cacheProcessadores podem organizar a cache em níveis como L1, L2 e L3. Em geral, os níveis mais próximos do core são menores e mais rápidos.
03

RAM

É a memória principal do computador. Durante a execução, mantém grande parte dos dados e instruções ativos da aplicação.

Como é acessadaCada localização da memória principal possui um endereço, permitindo que o processador solicite dados e instruções conforme o programa avança.
Característica importanteTem muito mais capacidade que a cache, porém maior custo de acesso. É volátil: seu conteúdo depende da alimentação do sistema.
04

Armazenamento

É a memória externa e não volátil usada para manter arquivos de programas e dados de forma persistente.

HDDUtiliza armazenamento magnético e componentes mecânicos. O tempo de acesso depende, entre outros fatores, do posicionamento físico necessário para alcançar os dados.
SSDUsa componentes de estado sólido, normalmente memória flash NAND. Elimina partes mecânicas e apresenta menores tempos de acesso que os discos magnéticos.

Leitura da hierarquia: registradores → cache → RAM → armazenamento. Ao descer na hierarquia, aumenta a capacidade disponível, mas também cresce o custo de buscar e movimentar os dados até a CPU.

2 · Cache e localidade

Por que a ordem de acesso aos dados importa?

Considere dois trechos de código que acessam a mesma quantidade de posições. A diferença está na ordem em que esses acessos acontecem.

Questão de investigação

Qual padrão parece mais favorável para encontrar rapidamente os próximos dados?

Compare as duas sequências antes de avançar para a explicação.

Padrão A · posições próximas
0→1→2→3→4
Padrão B · posições espalhadas
0→1000→2→800→5
  1. Os dois padrões acessam a mesma quantidade de posições?
  2. Em qual deles os próximos acessos tendem a ficar fisicamente mais próximos?
  3. Se a máquina consegue manter próximos dados usados recentemente, qual padrão tende a aproveitar melhor essa característica?
A cache explora justamente esse tipo de comportamento. Ela é uma memória pequena e rápida, próxima ao processador, que mantém dados e instruções com alta probabilidade de serem utilizados novamente em breve. Isso funciona porque programas costumam apresentar padrões de acesso previsíveis.

Localidade temporal

Ideia

Um dado usado recentemente tem chance de ser usado novamente em pouco tempo.

Exemplo de software

Uma variável acumuladora ou uma estrutura consultada várias vezes dentro do mesmo trecho do algoritmo.

Localidade espacial

Ideia

Depois de acessar uma posição, o programa frequentemente acessa posições próximas.

Exemplo de software

Percorrer uma lista ou um vetor na ordem em que seus elementos estão armazenados.

Quem coloca os dados na cache?

Normalmente, essa decisão é automática e fica a cargo do hardware do processador e da lógica de controle da cache. O programa solicita endereços de memória; a cache tenta atendê-los.

1

A CPU solicita um endereço. Antes de buscar diretamente na RAM, o nível de cache correspondente é consultado.

2

Se o dado está na cache, ocorre um hit. O valor pode ser entregue a partir desse nível mais rápido.

3

Se não está, ocorre um miss. O hardware busca em um nível inferior e traz para a cache um bloco que inclui o dado solicitado.

Importante: o programador normalmente não escolhe em qual posição da cache um dado ficará. Políticas implementadas pelo hardware controlam preenchimento e substituição.

O que o engenheiro de software pode fazer?

O código não controla diretamente a cache, mas determina o padrão de acesso aos dados. Isso cria oportunidades práticas para favorecer a localidade.

Percorrer em ordem

Quando possível, acessar vetores, matrizes e buffers de forma contígua favorece a localidade espacial.

Reutilizar enquanto está próximo

Se um conjunto de dados será usado várias vezes, realizar esse trabalho em sequência favorece a localidade temporal.

Processar em blocos

Em conjuntos grandes, trabalhar com partes menores pode manter o conjunto ativo de dados mais próximo da CPU por mais tempo.

Medir antes de otimizar

Uma organização mais complexa só se justifica quando as medições mostram que o acesso aos dados é relevante para o desempenho.

Ideia central: o engenheiro de software não coloca manualmente os dados na cache; ele organiza o código para que o hardware tenha mais oportunidades de reutilizar dados que já estão próximos.

Para o engenheiro de software, a pergunta prática é: como o meu código percorre e reutiliza os dados?

3 · RAM e conjunto de trabalho

Onde ficam os dados que a aplicação está usando?

A cache é pequena. A maior parte dos dados e instruções ativos da aplicação permanece na memória principal (RAM), de onde pode ser trazida para níveis mais próximos do processador conforme a execução avança.

RAM como memória principal

Maior capacidade

A RAM comporta muito mais dados que a cache, permitindo manter estruturas, objetos, buffers e instruções usados pela aplicação.

Maior custo de acesso

Ela é mais distante e mais lenta que a cache, por isso mover dados entre esses níveis influencia o desempenho.

Memória volátil

A RAM sustenta os dados durante a execução; para sobreviver ao fim da execução, informações precisam ser persistidas em armazenamento.

O que isso muda para o software?

O engenheiro decide quanto dado manter ativo e como processá-lo. Essas escolhas alteram o espaço ocupado e o padrão de movimentação na hierarquia.

Carregar tudo

É simples, mas grandes volumes podem ampliar muito o espaço de memória necessário.

Processar em blocos

Trabalhar com partes menores permite limitar o conjunto de dados ativo em cada etapa.

Evitar cópias desnecessárias

Estruturas intermediárias e duplicações aumentam a quantidade de memória usada pela aplicação.

Conjunto de trabalho (working set). Pense nele, neste momento, como o conjunto de dados que a aplicação está utilizando intensamente em uma fase da execução. Quanto maior e mais espalhado esse conjunto, mais difícil é mantê-lo próximo da CPU.

Próxima pergunta: se alguns dados precisam continuar existindo depois que a aplicação termina, onde eles devem ser mantidos?

4 · Persistência e E/S

Quando o dado precisa ser lido ou persistido

Ao sair da memória principal e chegar ao armazenamento persistente, o custo de movimentação ganha ainda mais importância.

ConceitoO que representaPergunta de Engenharia de Software
LatênciaTempo necessário para uma operação começar e produzir sua resposta.Quantas vezes meu programa inicia operações pequenas?
VazãoQuantidade de dados movimentada em determinado intervalo de tempo.Meu caso depende de muitas operações pequenas ou de grandes volumes contínuos?
Acesso sequencialLeitura ou escrita de dados em posições consecutivas.Posso organizar o fluxo para processar blocos contíguos?
Acesso aleatórioLeitura ou escrita em posições espalhadas.Minha estrutura exige saltos frequentes entre posições?
BufferÁrea temporária usada para acumular dados antes de transferi-los.Posso agrupar operações sem comprometer os requisitos da aplicação?

HDD

Armazenamento magnético com partes mecânicas. O padrão de acesso influencia fortemente o custo das operações porque a leitura depende do posicionamento físico do dispositivo.

SSD

Armazenamento em estado sólido baseado em memória flash. Sem partes mecânicas, apresenta menores tempos de acesso e maior desempenho de E/S que os discos magnéticos.

5 · Engenharia de Software

A mesma funcionalidade pode movimentar quantidades diferentes de dados

Do ponto de vista funcional, duas implementações podem estar corretas. Do ponto de vista da execução, porém, elas podem organizar, percorrer, manter e persistir dados de formas muito diferentes.

1 · Representar

Pergunta

Como os dados precisam ser estruturados para resolver o problema?

Impacto

Estruturas intermediárias, duplicações e referências espalhadas podem aumentar a quantidade de dados mantidos e movimentados.

2 · Percorrer

Pergunta

Em que ordem os dados serão acessados?

Impacto

Acessos sequenciais e reutilização de dados próximos tendem a favorecer a localidade; saltos frequentes podem reduzir esse aproveitamento.

3 · Manter

Pergunta

Quanto dado precisa ficar ativo ao mesmo tempo?

Impacto

Carregar tudo de uma vez, criar muitas cópias ou manter grandes estruturas temporárias amplia o conjunto de trabalho e a pressão sobre a RAM.

4 · Persistir

Pergunta

Com que frequência os dados precisam atravessar a fronteira entre memória e armazenamento?

Impacto

Muitas operações pequenas de leitura ou escrita podem custar mais do que agrupar operações em blocos quando os requisitos permitem.

Uma forma útil de pensar: requisito funcional → representação dos dados → padrão de acesso → movimentação → custo observado.

Pergunta de projeto: antes de otimizar uma linha de código, quais movimentações de dados essa implementação está provocando?

6 · Perfil da carga

O que está dominando a execução?

Um programa pode ficar lento por razões diferentes. Reconhecer o tipo de trabalho realizado ajuda a formular uma primeira hipótese sobre qual recurso está limitando uma fase da execução.

A

CPU-bound

O que domina: processamento. A maior parte do tempo é consumida executando cálculos.

Exemplos: cálculo numérico, compressão, criptografia e transformações intensivas.

Pergunta: a maior parte do trabalho consiste em calcular?

B

Memory-bound

O que domina: acesso e movimentação de dados entre CPU, cache e RAM.

Exemplos: grandes matrizes, coleções volumosas e acessos pouco localizados.

Pergunta: a CPU depende constantemente da chegada dos dados?

C

I/O-bound

O que domina: operações de entrada e saída.

Exemplos: leitura de muitos arquivos, gravações frequentes, logs e grandes transferências.

Pergunta: a execução passa uma parcela importante do tempo esperando leitura ou escrita?

Um mesmo programa pode mudar de perfil ao longo da execução. Carregar um arquivo pode ser uma fase dominada por E/S; processar seus dados pode ser dominado por CPU ou memória; salvar o resultado volta a introduzir E/S. Esses termos ajudam a descrever qual recurso domina uma fase ou uma carga, e não a rotular permanentemente uma aplicação.
Exercício de classificação

Identifique o perfil predominante da carga

CPU-bound · memory-bound · I/O-bound

Considere o trecho de execução descrito. Em cada caso, escolha o perfil que parece dominar o comportamento da aplicação.

  1. Um programa calcula números primos durante vários segundos e quase não realiza leitura ou escrita de arquivos.
  2. Um programa percorre repetidamente uma matriz muito grande já carregada na RAM, realizando apenas uma soma simples em cada elemento.
  3. Um programa grava milhares de pequenos registros em arquivos separados ao longo da execução.
  4. Um programa comprime centenas de imagens que já estão carregadas na memória, executando transformações matemáticas intensivas sobre cada uma.
  5. Um programa percorre um vetor de centenas de milhões de valores na RAM e executa pouquíssimas operações aritméticas sobre cada elemento.
  6. Um utilitário copia um arquivo de 20 GB de uma unidade de armazenamento para outra, sem realizar transformações relevantes nos dados.
  7. Um programa calcula repetidamente hashes criptográficos sobre um bloco de dados que já está disponível na memória.
  8. Um algoritmo percorre uma estrutura muito grande de objetos ligados por referências espalhadas na memória, realizando pouco cálculo em cada objeto.
  9. Um analisador lê um arquivo de log de vários gigabytes linha por linha, faz um teste simples em cada linha e grava apenas um pequeno resumo no final.

Como responder

  1. Escolha entre CPU-bound, memory-bound e I/O-bound.
  2. Indique qual pista do enunciado levou à sua classificação.

Desafio · uma aplicação, vários momentos

Uma aplicação executa quatro etapas:

  1. lê 4 GB de dados de um SSD;
  2. percorre várias vezes uma grande estrutura já carregada na RAM para reorganizar os registros;
  3. executa um cálculo estatístico pesado sobre os dados reorganizados;
  4. grava um resumo de 5 MB em disco.

Classifique cada etapa

  1. Qual perfil parece predominante em cada fase?
  2. A aplicação inteira precisa receber um único rótulo?
  3. Sem medir o tempo de cada fase, é possível afirmar qual delas domina o tempo total?

Experimento final

Mesmos dados, mesma resposta, percursos diferentes

Vamos comparar implementações que realizam o mesmo trabalho lógico, mas acessam ou movimentam os dados de maneiras diferentes. A sequência será sempre a mesma: entender o percurso → formular uma hipótese → executar → interpretar a medição.

Pergunta do experimento: se duas implementações processam os mesmos dados e produzem o mesmo resultado, a forma como elas percorrem ou gravam esses dados pode alterar o tempo de execução?
Antes do código visualize o percurso

Imagine uma matriz 3 × 4

Na memória, vamos representá-la como uma sequência linear de posições:

linha 0 →  0   1   2   3
linha 1 →  4   5   6   7
linha 2 →  8   9  10  11

A posição de um elemento é calculada por linha * COLUNAS + coluna.

Dois percursos possíveis

Por linhas

0 → 1 → 2 → 3 → 4 → 5 → ...

Por colunas

0 → 4 → 8 → 1 → 5 → 9 → ...

  1. Qual percurso acessa mais posições consecutivas?
  2. Qual deles parece favorecer melhor a localidade espacial?
  3. Qual você espera que seja mais rápido? Registre a hipótese antes de executar.
Parte A · Acesso em memória Python

O que deve permanecer igual?

As duas funções devem percorrer todos os elementos e produzir a mesma soma. O que muda é apenas a ordem de acesso.

Percurso por linhas

A linha varia no laço externo; dentro dela, percorremos as colunas.

Percurso por colunas

A coluna varia no laço externo; dentro dela, percorremos as linhas.

Antes de programar

  1. As duas funções realizarão a mesma quantidade de somas?
  2. Qual delas tende a acessar endereços consecutivos?
  3. Qual resultado você espera observar no tempo de execução?
Infraestrutura fornecida — implemente apenas os dois percursos
from time import perf_counter

LINHAS = 1500
COLUNAS = 1500

dados = bytearray([1]) * (LINHAS * COLUNAS)


def percorrer_por_linhas():
    total = 0
    # percorra linha por linha
    # use: posicao = linha * COLUNAS + coluna
    return total


def percorrer_por_colunas():
    total = 0
    # percorra coluna por coluna
    # use: posicao = linha * COLUNAS + coluna
    return total


def medir(nome, funcao):
    inicio = perf_counter()
    resultado = funcao()
    fim = perf_counter()
    print(f"{nome}: resultado={resultado} | tempo={fim - inicio:.4f}s")

medir("Por linhas", percorrer_por_linhas)
medir("Por colunas", percorrer_por_colunas)

Parte B · Persistência mesmo conteúdo · estratégias diferentes

Agora mude o tipo de movimentação

Em vez de mudar a ordem de acesso à memória, vamos manter o mesmo conteúdo e mudar como ele é enviado ao arquivo.

Linha a linha

O programa chama write() repetidamente dentro de um laço.

Em bloco

O programa reúne o conteúdo e realiza uma chamada de escrita com um bloco maior.

Formule a hipótese

  1. As duas estratégias gravam a mesma quantidade de linhas?
  2. Qual delas realiza mais chamadas de write() no código Python?
  3. Qual você espera que tenha menor tempo? Por quê?
Ponto de partida — implemente as duas estratégias
resultados = [f"{i};{i*i}\n" for i in range(200_000)]


def gravar_linha_a_linha():
    with open("saida_linhas.txt", "w", encoding="utf-8") as arquivo:
        # percorra resultados e use arquivo.write(...)
        pass


def gravar_em_bloco():
    with open("saida_bloco.txt", "w", encoding="utf-8") as arquivo:
        # reúna as linhas e faça uma escrita em bloco
        pass


medir("Linha a linha", gravar_linha_a_linha)
medir("Em bloco", gravar_em_bloco)
Fechamento do experimento interpretação

Compare as duas partes

Na Parte A, mudamos a ordem de acesso. Na Parte B, mudamos a forma de agrupar operações de escrita. Nos dois casos, a funcionalidade permanece equivalente, mas o percurso dos dados muda.

Explique com os conceitos da aula

  1. Onde aparece a localidade espacial na Parte A?
  2. Onde aparecem latência e agrupamento de operações na Parte B?
  3. Que decisão de Engenharia de Software foi alterada em cada experimento?
Ideia que deve ficar: desempenho não depende apenas do algoritmo em sentido abstrato. A forma como o software organiza, percorre e movimenta dados também cria custos que podem ser observados por medição.
