Na Aula 03 vimos a CPU buscar, interpretar e executar instruções. Agora vamos conectar esse modelo ao trabalho cotidiano de quem desenvolve software: o que existe entre uma linha de código e as operações que o processador realmente executa?

Primeira ideia-chave

O mesmo programa aparece em representações diferentes

Uma linguagem de alto nível foi construída para pessoas expressarem algoritmos e regras. A CPU, por outro lado, interpreta instruções definidas pela arquitetura do processador. Entre esses níveis existe tradução.

1 · Código-fonteExpressão para pessoasresultado = a + b
→
2 · TraduçãoCompilador, interpretador ou runtimeTransforma ou coordena a execução.
→
3 · InstruçõesOperações compatíveis com uma ISAMovimentar, somar, comparar, desviar...
→
4 · HardwareCPU executa instruções de máquinaRegistradores, ALU, memória e controle participam.
Importante: esse fluxo é uma abstração didática. Compiladores, máquinas virtuais, bytecode, bibliotecas, loaders e otimizações podem acrescentar etapas. Hoje queremos compreender a relação essencial entre os níveis.

Ver resposta orientadora

O código-fonte passa por tradução ou por um ambiente de execução; a CPU executa instruções compatíveis com sua ISA. Em outra arquitetura, o algoritmo pode ser o mesmo, mas as instruções de máquina e os registradores disponíveis podem mudar.

Caminhos diferentes

Compilado e interpretado não significam “hardware” e “não hardware”

C e Python são úteis para comparar caminhos de execução. O ponto central é que, cedo ou tarde, instruções nativas precisam ser executadas por um processador.

Um programa em C

O compilador pode transformar o código-fonte em código de máquina para uma arquitetura-alvo antes da execução.

C→compilador→x86-64 / ARM64→CPU

Um programa em Python

O código normalmente passa pelo runtime da implementação Python. Esse runtime, por sua vez, é software nativo executado pelo processador.

Python→runtime→operações internas→CPU
Para Engenharia de Software, a pergunta útil não é apenas “qual linguagem é mais rápida?”, mas qual caminho de execução, quais abstrações e quais custos a solução introduz para o problema em questão?

Código precisa virar estado

Nome, valor, endereço e registrador são coisas diferentes

Em uma linguagem de programação usamos nomes. Durante a execução, valores precisam estar representados em algum lugar. Para raciocinar sobre a máquina, precisamos separar esses conceitos.

Nome no códigoa

Identificador utilizado pelo programador.

Representação didática de uma posição endereçável. Os endereços abaixo são fictícios.

RegistradorR1

Contrato entre software e processador

ISA: quais instruções a máquina oferece ao software?

A arquitetura do conjunto de instruções — ISA — define aspectos visíveis para o software de baixo nível: instruções, registradores, formas de operar dados e regras de execução. x86-64 e ARM64 são exemplos de ISAs diferentes.

Assembly é uma representação simbólica

Em vez de escrever sequências binárias, usamos mnemônicos como MOV, ADD e CMP. O montador transforma essa representação em código de máquina.

MOVADDSUBCMPJMPRET

Uma instrução faz uma coisa relativamente elementar

Uma expressão de alto nível pode exigir várias instruções. Além disso, um compilador pode reorganizar ou substituir operações quando otimiza o programa.

Limite da aula: não vamos memorizar sintaxe x86-64, convenções de chamada, stack, flags ou modos de endereçamento. Vamos apenas observar instruções e estado.

Agora uma arquitetura real

Observe x86-64 sem transformar a aula em um curso de Assembly

Vamos usar uma ferramenta no navegador para executar e depurar um programa mínimo. O objetivo é observar registradores mudando após cada instrução.

Ferramenta sugerida

x86-64 Playground

Editor, emulador e depurador x86-64 executado no navegador. Para esta atividade, use NASM e avance pelo programa instrução por instrução.

Abrir x86-64 Playground ↗
  1. Abra a ferramenta e escolha um exemplo/projeto NASM.
  2. Substitua o código pelo exemplo ao lado.
  3. Compile e entre no modo de depuração.
  4. Avance até executar as três primeiras instruções.
  5. Observe RAX e RBX após cada passo.
NASM · x86-64 Linuxfoco: 3 primeiras instruções
global _start
section .text

_start:
    mov rax, 7
    mov rbx, 5
    add rax, rbx

    ; encerramento do programa — não é o foco da aula
    mov rdi, rax
    mov rax, 60
    syscall
Depois de mov rax, 7, RAX deve conter 7. Depois de mov rbx, 5, RBX deve conter 5. Depois de add rax, rbx, RAX deve conter 12.

Por que x86-64? É uma arquitetura real muito comum em computadores pessoais e servidores. Na Aula 05 vamos comparar esse universo com outras arquiteturas, especialmente ARM, sem assumir que uma delas é “a forma universal” de executar programas.

Do C para Assembly

O compilador também pode ser observado

Uma segunda ferramenta interessante para Engenharia de Software é o Compiler Explorer. Ela permite colocar uma função em C de um lado e visualizar o Assembly produzido por diferentes compiladores e arquiteturas do outro.

Cfunção mínima

    return a + b;
}
O Assembly exato pode variar conforme compilador, versão, arquitetura e nível de otimização.

Prática com uma linguagem conhecida

Use Python para modelar uma CPU mínima

Como o foco não é dominar Assembly, podemos usar Python para tornar explícitos memória, registradores e instruções. O simulador abaixo é intencionalmente simples: ele não é uma CPU real, mas preserva a ideia de carregar, operar e armazenar.

Pythoncomplete os TODOs
memoria = {
    0x1000: 7,
    0x1008: 5,
    0x1010: 0,
}

registradores = {"R1": 0, "R2": 0, "R3": 0}

# LOAD R1, [0x1000]
registradores["R1"] = memoria[0x1000]

# LOAD R2, [0x1008]
registradores["R2"] = memoria[0x1008]

# TODO 1: ADD R3, R1, R2
registradores["R3"] = __________________________

# TODO 2: STORE [0x1010], R3
memoria[0x1010] = ______________________________

print(registradores)
print(memoria)

O que praticar

  • Complete somente duas linhas.
  • Antes de executar, escreva o resultado esperado.
  • Confirme que R3 contém 12.
  • Confirme que memoria[0x1010] passa a conter 12.
  • Altere os valores 7 e 5 e faça uma nova previsão.
Não confunda modelo com implementação: os dicionários Python representam memória e registradores apenas para facilitar nosso raciocínio.

Python também tem níveis intermediários

Uma função Python não vira diretamente ADD RAX, RBX

Uma experiência simples com o módulo dis permite observar instruções internas da máquina virtual Python. Elas não são instruções x86-64: são outra representação no caminho de execução.

Pythonexecute no Colab ou Python local
import dis

def soma(a, b):
    return a + b

dis.dis(soma)
A saída depende da versão do Python. Observe a existência de operações internas de carregamento, operação e retorno, sem memorizar os nomes.

Onde o sistema operacional entra?

O programa não recebe a máquina inteira para si

Quando executamos um programa em um sistema operacional moderno, ele é colocado em um ambiente controlado. Nesta aula basta reconhecer quatro responsabilidades que estudaremos com mais profundidade depois.

01

Criar o processo

O SO organiza uma instância de execução do programa.

02

Organizar memória

Código e dados precisam de um espaço de endereçamento utilizável pelo processo.

03

Compartilhar CPU

O programa compete por tempo de processador com outros processos e threads.

04

Oferecer serviços

Arquivos, rede e dispositivos são acessados por abstrações controladas pelo sistema operacional.

Mais adiante veremos que esse ponto é decisivo para concorrência, desempenho, isolamento e segurança. Por enquanto, guarde a ideia: o software executa sobre abstrações fornecidas pelo SO e sobre instruções fornecidas pela arquitetura.

Por que um engenheiro de software precisa disso?

Porque “funciona no meu computador” é uma explicação insuficiente

Entender a execução ajuda a raciocinar sobre compatibilidade, desempenho, depuração e limites das abstrações.

01

Compatibilidade

Arquitetura, sistema operacional e runtime condicionam onde um artefato pode executar.

02

Desempenho

Uma operação de alto nível pode resultar em várias operações de baixo nível e acessos à memória.

03

Depuração

Logs e exceções mostram uma camada; depuradores, traces e perfis permitem observar outras.

04

Projeto

Escolher linguagem, runtime e plataforma também é escolher custos e restrições de execução.
