Primeira ideia

O código-fonte expressa uma intenção; a máquina executa operações mais elementares

Linguagens de alto nível nos permitem trabalhar com nomes, tipos, decisões, repetições e funções. Essas abstrações precisam ser traduzidas para operações pertencentes à máquina que executará o programa.

C · código-fontecomece simples
int soma(int a, int b) {
    return a + b;
}
A intenção é simples para nós: receber dois inteiros, somá-los e devolver o resultado.
O nome da variável ajuda o programador

A CPU não precisa conhecer os identificadores a e b da mesma forma que nós.

A soma precisa virar uma operação da máquina

O compilador selecionará instruções adequadas ao alvo para realizar o comportamento pedido.

Uma linha não significa uma instrução

Uma construção de alto nível pode desaparecer, combinar-se com outras ou gerar várias instruções.

O que o experimento mostrou: o código que escrevemos não é o código que a CPU executa. Entre essas duas representações existe uma etapa de tradução.

Segunda ideia

O compilador precisa saber para qual máquina está produzindo código

“Compilar” não significa apenas transformar uma linguagem em outra. O compilador produz código para um alvo. Esse alvo condiciona quais instruções e recursos podem aparecer no resultado.

1 · FonteCódigo-fonte

Expressa o algoritmo usando as abstrações da linguagem.

2 · FerramentaCompilador

Traduz e organiza o programa.

3 · TargetArquitetura-alvo

Indica para qual máquina o código será gerado.

4 · ResultadoCódigo de máquina

Usa instruções válidas para o alvo escolhido.

Target A

x86-64

Arquitetura amplamente usada em desktops, notebooks e servidores com processadores Intel e AMD.

Target B

ARM64 / AArch64

Arquitetura comum em smartphones, sistemas embarcados, computadores e servidores modernos.

Engenharia de Software

Build target

Um projeto pode gerar artefatos diferentes a partir do mesmo repositório porque cada build pode mirar um alvo diferente.

O que mudou? Não foi o algoritmo. Mudou o vocabulário de máquina disponível para realizar esse algoritmo. Agora temos evidência suficiente para formalizar a ideia de ISA.

Formalizando o que observamos

A ISA funciona como um contrato entre software de baixo nível e processador

A Instruction Set Architecture define a interface arquitetural que o código de máquina utiliza. O compilador não pode inventar qualquer operação: ele precisa produzir instruções pertencentes ao conjunto oferecido pelo alvo.

O que esse contrato descreve?

Instruções disponíveisQuais operações podem ser solicitadas ao processador.
Registradores visíveisQuais registradores fazem parte da interface arquitetural.
Operandos e acesso a dadosComo as instruções trabalham com valores, registradores e memória.
Representações suportadasQuais tamanhos e formatos de dados a arquitetura expõe.

Limite didático

ISA não significa decorar Assembly

O objetivo desta aula é reconhecer a existência do contrato e suas consequências para software.

  • Não memorizar listas de instruções.
  • Não decorar todos os registradores.
  • Não estudar modos de endereçamento em detalhe.
  • Não escrever aplicações extensas em Assembly.
Retome a Aula 03: arquitetura e organização não são a mesma coisa. Dois processadores podem implementar a mesma ISA e ter organizações internas diferentes. Para compatibilidade de binários, o contrato arquitetural importa diretamente.

32 × 64 bits

O rótulo do download representa uma característica real do alvo

Termos como x86, x64 e ARM64 aparecem em instaladores, builds e documentação. Para Engenharia de Software, interessa compreender o suficiente para escolher, produzir e distribuir o artefato correto.

x86 / 32 bits

Geralmente identifica uma variante de 32 bits da família x86.

x64 / x86-64

Identifica a extensão de 64 bits da família x86 usada amplamente em PCs e servidores.

ARM64

Identifica a arquitetura ARM de 64 bits, também chamada AArch64.

O que “64 bits” não quer dizer

Não significa automaticamente “duas vezes mais rápido”. A largura arquitetural está associada a aspectos como registradores, endereçamento e instruções disponíveis, mas desempenho depende de muitos outros fatores.

Para esta aula: não precisamos calcular limites de espaço de endereçamento nem aprofundar ponteiros. Precisamos reconhecer que 32 e 64 bits fazem parte do contrato da plataforma e afetam compatibilidade.

Binário e plataforma

Mesma ISA não significa automaticamente mesmo ambiente de execução

Quando o código-fonte vira um artefato nativo, a arquitetura-alvo é apenas uma das restrições. O sistema operacional e as interfaces binárias esperadas pelo programa também participam da compatibilidade.

Código-fonte

É a representação mantida pela equipe de desenvolvimento.

Arquitetura / ISA

Define o vocabulário de máquina que o binário pode usar.

Sistema operacional e ABI

Definem convenções e interfaces que o programa nativo espera encontrar.

Bibliotecas e runtime

Podem acrescentar outras dependências ao ambiente de execução.

Exemplo de raciocínio

Um computador Windows x86-64 e um computador Linux x86-64 compartilham a arquitetura de processador, mas isso não transforma automaticamente um executável nativo produzido para Windows em um executável Linux.

Da mesma forma, duas máquinas usando o mesmo sistema operacional podem precisar de artefatos diferentes se uma for x86-64 e outra ARM64.

Compatibilidade é uma interseção: o artefato precisa ser adequado à arquitetura e ao ambiente para o qual foi construído.
Experimento 5

Mesmo target, outra compilação

extensão · otimização

Objetivo: perceber que o código de máquina também pode mudar sem trocar o código-fonte nem a ISA.

Claço simples
int soma_vetor(const int *v, int n) {
    int total = 0;

    for (int i = 0; i < n; i++) {
        total += v[i];
    }

    return total;
}
  1. Mantenha um compilador x86-64.
  2. Observe a saída sem otimização ou com -O0.
  3. Depois compare com -O2.
  4. Registre mudanças visíveis na saída.
Não conclua “mais rápido” apenas porque há menos linhas. O experimento mostra que o compilador toma decisões diferentes. Medir desempenho é outro problema, que será tratado em outro momento.
