Primeira mudança de representação

O código que escrevemos não é o código que a CPU executa

Linguagens de programação existem para que possamos expressar algoritmos de maneira compreensível. A CPU, por outro lado, executa instruções definidas pela arquitetura do processador.

1 · Código-fonteUma representação para programadoresresultado = a + b
→
2 · Tradução / ambienteO programa é preparado para execuçãoCompilador, interpretador ou runtime participam desse caminho.
→
3 · MáquinaInstruções executáveis pela CPUTransferir dados, operar, armazenar, desviar...
Limite didático: nesta aula não vamos estudar linker, loader, bytecode, JIT ou formatos de executável. Precisamos apenas reconhecer que existe uma transformação entre o código-fonte e as instruções executadas.

Exemplo 1

C

O compilador transforma o programa em código adequado à plataforma de destino antes da execução.

fonte→compilação→executável

Exemplo 2

Python

Um runtime participa da execução do programa. O caminho interno é diferente do C, mas a CPU continua executando instruções de máquina no nível mais baixo.

fonte→runtime→execução

Antes das instruções

Nome, valor e endereço não são a mesma coisa

Quando programamos, usamos nomes. Durante a execução, os dados precisam estar representados e localizados em algum lugar do sistema. Para começar a enxergar essa diferença, vamos usar endereços fictícios.

aNome

É o identificador usado no código-fonte para nos referirmos a um dado.

7Valor

É o conteúdo associado à variável neste momento da execução.

0x1000Endereço

Representa uma posição onde o dado pode estar localizado na memória.

EndereçoNome no códigoConteúdo

0x1008resultado?

Segunda mudança de representação

Uma expressão pode virar várias operações elementares

Vamos usar uma linguagem de máquina simplificada. Ela não representa a sintaxe exata de x86 ou ARM; serve apenas para enxergar a decomposição da operação.

Código de alto nível

resultado = a + b

Uma expressão compacta para o programador.

LOAD R1,[0x1000]Carregue o valor de a em um registrador.
LOAD R2,[0x1004]Carregue o valor de b em outro registrador.
ADD R3,R1,R2Some os valores e mantenha o resultado em R3.
STORE [0x1008],R3Grave o resultado na posição associada a resultado.
R17
R25
R312
Mem[0x1008]12
Importante: LOAD, ADD e STORE são pseudoinstruções didáticas. O objetivo é compreender a ideia de movimentar dados, operar sobre eles e guardar resultados.

Buscar, interpretar e executar — agora com significado

A instrução simplificada ADD R3,R1,R2 também precisa passar pelo ciclo que estudamos na Aula 03.

1

Buscar

A CPU obtém a próxima instrução que deve ser executada.

2

Interpretar

A unidade de controle identifica a operação e os operandos envolvidos.

3

Executar

A operação é realizada usando os recursos internos necessários.

4

Atualizar o estado

Registradores ou memória podem receber o resultado da operação.

APS 1 · atividade assíncrona

Do código-fonte à execução

A atividade usa o mesmo modelo da aula. Não é necessário instalar compilador, simulador ou ferramenta adicional. O foco é interpretar, rastrear e explicar.

1

Preveja o programa

Considere:

Trecho em C
int x = 4;
int y = 3;
int z = x * 2 + y;
  • Qual será o valor final de z?
  • Que operações precisam acontecer?
2

Organize os dados

Use os endereços fictícios 0x2000, 0x2004 e 0x2008 para representar x, y e z.

  • Diferencie nome, endereço e valor.
  • Mostre o estado inicial da memória.
3

Rastreie instruções

Interprete uma sequência fornecida com operações LOAD, MUL, ADD e STORE.

  • Preencha os registradores passo a passo.
  • Explique quando o resultado é gravado na memória.

Entrega

O que deve ser registrado

  1. Previsão do resultado do programa.
  2. Tabela com nome, endereço fictício e valor.
  3. Rastreamento da sequência de instruções.
  4. Uma explicação curta relacionando código, memória, registradores e execução.
Não é objetivo da APS: memorizar Assembly real, registradores x86/ARM, stack, heap, memória virtual, calling convention ou detalhes de compiladores.
