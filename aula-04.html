Para abrir a Aula 04: quem transforma nossa intenção em instruções válidas para uma máquina concreta?

Primeira ideia

O código-fonte expressa uma intenção; a máquina executa instruções

Linguagens de alto nível nos permitem trabalhar com nomes, tipos, decisões, repetições e funções. Essas abstrações precisam ser traduzidas para operações pertencentes à máquina que executará o programa.

C · código-fonte
int soma(int a, int b) {
    return a + b;
}

O que essa função expressa?

Para nós, a intenção é direta: receber dois inteiros, somá-los e devolver o resultado.

Mas a CPU não recebe os nomes a e b dessa forma. Na execução nativa, ela trabalha com instruções, registradores, endereços e valores.

Uma linha de C não corresponde a uma instrução da CPU. Uma construção de alto nível pode gerar várias operações; com otimizações, algumas também podem ser combinadas ou eliminadas.

Abstração

O código ajuda quem programa

Nomes e tipos

preco, frete e total carregam significado para o desenvolvedor.

Estruturas

if, for e funções expressam comportamento sem exigir detalhes da máquina.

Tradução

O compilador aproxima o programa da máquina

Decisões de baixo nível

O compilador escolhe instruções, registradores e formas de acesso adequadas ao alvo.

Mesmo comportamento

Representações de máquina diferentes podem implementar a mesma intenção do código-fonte.

O código que escrevemos não é o código que a CPU executa. Entre essas duas representações existe uma etapa de tradução.
Experimento 1

Faça uma previsão e abra o Compiler Explorer

hipótese → observação
  1. Antes de abrir a ferramenta, descreva o que a máquina precisa fazer para executar return a + b;.
  2. Abra o Compiler Explorer com a linguagem C.
  3. Escolha um compilador x86-64.
  4. Cole a função soma e observe o Assembly.
  5. Procure apenas evidências de valores, operação e retorno.
Abrir Compiler Explorer ↗Não é necessário traduzir cada instrução.

Segunda ideia

O compilador precisa saber para qual máquina produzir código

Ao instalar um programa, opções como x64 e ARM64 indicam que um programa nativo precisa ser preparado para uma arquitetura capaz de compreender as instruções geradas.

3 · DestinoArquitetura-alvoDefine para qual família de processadores o código será produzido.

Target A

x86-64

Arquitetura amplamente usada em desktops, notebooks e servidores com processadores Intel e AMD.

Exemplos de registradores

eax, edi, rax.

Target B

ARM64 / AArch64

Arquitetura comum em smartphones, sistemas embarcados, computadores e servidores modernos.

Exemplos de registradores

w0, w1, x0, x1.

A saída pode variar. Compiladores e versões diferentes podem escolher instruções distintas mesmo para a mesma arquitetura. O padrão importante é que, ao trocar o alvo, o compilador passa a trabalhar com os recursos disponíveis naquele alvo.
Experimento 2

Compare x86-64 e ARM64

mesmo código · alvos diferentes
  1. Use a função int dobro(int x){ return x * 2; }.
  2. Compile para x86-64 com -O2.
  3. Abra uma segunda saída ARM64/AArch64, também com -O2.
  4. Localize nomes de registradores e instruções nas duas saídas.
  5. Confirme que o código C e o comportamento esperado permanecem iguais.
Abrir Compiler Explorer ↗O objetivo é comparar evidências, não decorar Assembly.

Formalizando o que observamos

A ISA funciona como um contrato entre software e processador

Quando o compilador produz código para x86-64 ou ARM64, o resultado precisa respeitar a Instruction Set Architecture (ISA) daquele alvo.

Ideia-chave

A ISA define o que a máquina oferece ao software

Ela especifica o vocabulário arquitetural visível ao software de baixo nível: instruções, registradores, formatos de instrução, dados e formas de acesso à memória.

O contrato define

Recursos visíveis ao software

Instruções

Operações como somar, comparar, mover dados e desviar a execução.

Registradores

Quais registradores podem ser usados e como são identificados.

Formatos e operandos

Como uma instrução representa a operação e os valores envolvidos.

Acesso à memória

Como instruções podem localizar e manipular dados armazenados.

Uma distinção importante

A ISA não é o processador inteiro

Mesma ISA, organizações diferentes

Dois processadores podem executar a mesma ISA e ter caches, pipelines, frequências e números de núcleos diferentes.

Arquitetura × organização

A ISA pertence à arquitetura visível ao software; a organização descreve como esse contrato é implementado internamente.

Em uma frase: a ISA diz o que a máquina oferece ao software; a organização diz como o processador realiza isso.

A ISA é necessária, mas não descreve toda a plataforma. Windows x86-64 e Linux x86-64 compartilham a arquitetura do processador, mas ainda diferem em sistema operacional, ABI, bibliotecas e convenções de execução.
