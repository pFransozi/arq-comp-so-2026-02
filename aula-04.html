Primeira ideia

O código-fonte descreve o comportamento; a máquina executa instruções

Linguagens de alto nível nos permitem trabalhar com nomes, tipos, decisões, repetições e funções. O processador, porém, executa instruções pertencentes à arquitetura para a qual o programa foi preparado.

01

Expressar

O código-fonte descreve o comportamento desejado usando abstrações da linguagem.

02

Traduzir

O compilador transforma essa descrição em uma representação adequada ao alvo.

03

Gerar

O resultado utiliza instruções e registradores válidos para a arquitetura escolhida.

04

Executar

A CPU busca, decodifica e executa as instruções produzidas.

C · código-fonteexemplo mínimo
int soma(int a, int b) {
    return a + b;
}
Para quem programa, a intenção é direta: receber dois inteiros, somá-los e devolver o resultado.

O que não aparece no código?

Não escolhemos explicitamente registradores, formato de instrução ou a sequência exata de operações da máquina. Essas decisões são tomadas durante a tradução para um alvo concreto.

Importante: não existe uma regra “1 linha de C = 1 instrução da CPU”. Uma construção de alto nível pode gerar várias instruções; otimizações também podem combiná-las ou eliminá-las.

Segunda ideia

O compilador precisa saber para qual máquina está produzindo código

Ao instalar um programa, rótulos como x64 e ARM64 indicam que um mesmo produto pode precisar de artefatos diferentes. O código-fonte pode permanecer o mesmo, mas a tradução precisa considerar o destino.

Formalizando o que observamos

A ISA funciona como um contrato entre software e processador

A Instruction Set Architecture define a interface arquitetural que o software de baixo nível pode usar: instruções, registradores, formatos, operandos e formas de acesso à memória.

Quais operações podem ser representadas e executadas.

A ISA não é o processador inteiro

Dois processadores podem implementar a mesma ISA e ainda serem diferentes por dentro: caches, pipeline, frequência, número de núcleos e unidades internas podem variar.

Arquitetura × organização: a ISA pertence à arquitetura visível ao software. A organização descreve como o processador implementa esse contrato internamente.
Em uma frase: a ISA diz o que a máquina oferece ao software; a organização diz como o processador realiza isso.

Compatibilidade e suporte

Cada plataforma aumenta o espaço de teste

Compatibilidade

Mesma ISA não garante automaticamente o mesmo binário em sistemas operacionais diferentes.

Suporte

Mais plataformas significam mais combinações para construir, testar, documentar e manter.

Exemplo: Windows x86-64 ≠ Linux x86-64 e Windows x86-64 ≠ Windows ARM64. Em cada caso alguma dimensão importante da plataforma mudou.
