Sabemos onde o dado está. Mas o que está armazenado?

Registradores, cache, RAM e armazenamento mantêm sequências de bits. O hardware não encontra uma etiqueta dizendo “isto é um número negativo” ou “isto é uma letra”. O significado depende da forma como os bits são interpretados.

1 · Sistemas posicionais

Antes do binário: por que a posição importa?

Comece pelo sistema que já usamos todos os dias. Em 538, os algarismos 5, 3 e 8 não valem apenas cinco, três e oito: cada um é multiplicado pelo peso da posição em que aparece.

53810 = 8 × 1 + 3 × 10 + 5 × 100 = 538
DígitoPosiçãoPesoContribuição
8unidades10⁰ = 18 × 1 = 8
3dezenas10¹ = 103 × 10 = 30
5centenas10² = 1005 × 100 = 500

É por isso que o sistema é chamado de posicional: o valor de um dígito depende do próprio dígito e da posição que ele ocupa.

O que significa a base?

A base informa quantos símbolos diferentes podem ser usados em cada posição. Ela também define os pesos das posições, contados da direita para a esquerda: base⁰, base¹, base², base³...

Base 10Decimal

Leia da direita para a esquerda:
1000 = 10³ ← 100 = 10² ← 10 = 10¹ ← 1 = 10⁰

Base 2Binário

Leia da direita para a esquerda:
16 = 2⁴ ← 8 = 2³ ← 4 = 2² ← 2 = 2¹ ← 1 = 2⁰

Base 16Hexadecimal

Leia da direita para a esquerda:
4096 = 16³ ← 256 = 16² ← 16 = 16¹ ← 1 = 16⁰

Regra para ler qualquer sistema posicional: comece pela posição mais à direita, cujo peso é base⁰ = 1, e avance para a esquerda: base¹, base², base³...

A mesma regra no binário

No número 1011₂, começamos pelo bit mais à direita. Como a base é 2, os pesos crescem assim: 1, 2, 4 e 8.

BitPotênciaPesoContribuição
12⁰11 × 1 = 1
12¹21 × 2 = 2
02²40 × 4 = 0
12³81 × 8 = 8
10112 = 1 + 2 + 0 + 8 = 1110

A base muda a escrita, não o valor

Exemplo

4210 = 1010102 = 2A16

As três notações representam a mesma quantidade.

Como saber qual base está sendo usada?

Nesta aula

Usaremos um índice para indicar a base: 1011₂, 42₁₀ e 2A₁₆. Em programação, também são comuns prefixos como 0b para binário e 0x para hexadecimal.

Próximo passo: no computador, a base 2 é especialmente importante porque cada posição pode assumir apenas dois estados. Agora vamos ver o que acontece quando combinamos vários bits.

2 · Bits, bytes e capacidade

De um bit a muitos padrões

Um bit pode assumir apenas dois estados: 0 ou 1. Quando adicionamos outro bit, cada padrão existente pode terminar em 0 ou em 1. Por isso, a quantidade de combinações dobra a cada novo bit.

Quantidade de bitsPadrões possíveisExemplos
1 bit2¹ = 20, 1
2 bits2² = 400, 01, 10, 11
3 bits2³ = 8000 até 111
4 bits2⁴ = 160000 até 1111
n bits → 2n padrões possíveis

Observe o crescimento: 1 bit gera 2 padrões; 2 bits geram 4; 3 bits geram 8; 4 bits geram 16. Cada novo bit dobra a quantidade de padrões disponíveis.

O que acontece com 8 bits?

Com 8 bits temos 2⁸ = 256 padrões diferentes. Esses padrões vão de 00000000 até 11111111.

00000000primeiro padrão0
00000001próximo padrão1
11111110penúltimo padrão254
11111111último padrão255
256 padrões não significa que o maior valor seja 256. Se interpretarmos os 8 bits como um inteiro sem sinal, o primeiro padrão representa 0. Por isso, os 256 valores possíveis vão de 0 a 255.
1 posição bináriaBit

É a menor unidade usada aqui para representar informação. Pode assumir 0 ou 1.

8 bitsByte

Um byte reúne 8 bits. Portanto, possui 2⁸ = 256 padrões possíveis.

Depende da arquiteturaPalavra

É uma unidade de dados associada à organização da máquina. Seu tamanho não precisa ser igual a um byte.

Mais bits, mais possibilidades

LarguraPadrões possíveisSe forem inteiros sem sinal

16 bits2¹⁶ = 65.5360 a 65.535

  1. Quantos padrões diferentes podem ser formados?
  2. Se todos forem usados como inteiros sem sinal, qual é o menor valor?
  3. Qual é o maior valor?

Resposta esperada: 32 padrões, de 0 a 31.

Ideia central: a quantidade de bits determina quantos padrões podem existir. O significado de cada padrão — número positivo, negativo, caractere ou outra informação — depende da forma como ele será interpretado.

3 · Decimal e binário

Converter é reinterpretar o valor em outra base

Vamos trabalhar apenas com inteiros neste bloco. O objetivo é compreender o mecanismo, não memorizar tabelas extensas.

Binário → decimal

Somamos as potências de 2 correspondentes às posições que contêm 1.

101101₂
1×2⁵ + 0×2⁴ + 1×2³ + 1×2² + 0×2¹ + 1×2⁰
32 + 8 + 4 + 1 = 45₁₀

Decimal → binário

Uma técnica é dividir sucessivamente por 2 e registrar os restos. Lemos os restos de baixo para cima.

42 ÷ 2 = 21 · resto 0
21 ÷ 2 = 10 · resto 1
10 ÷ 2 = 5 · resto 0
5 ÷ 2 = 2 · resto 1
2 ÷ 2 = 1 · resto 0
1 ÷ 2 = 0 · resto 1
42₁₀ = 101010₂

5 · Os mesmos bits

Um padrão de bits não carrega sozinho o seu tipo

A mesma sequência pode representar valores diferentes quando usamos convenções diferentes. Essa ideia é central para compreender tipos, memória e instruções.

11111111
Inteiro sem sinal de 8 bits255.
Inteiro com sinal de 8 bits em complemento de dois−1.
HexadecimalFF. O hexadecimal descreve o padrão; não define sozinho se ele é positivo ou negativo.

O tipo orienta a interpretação

Quando um programa declara ou manipula um dado, a linguagem, o compilador e a arquitetura aplicam regras que determinam como aquele padrão deve ser tratado.

Memória guarda padrões

Uma região de memória não precisa “saber” semanticamente se contém um número, um caractere ou parte de uma instrução. Esse significado surge do contexto de uso.

dado = bytes([0xFF])

print(int.from_bytes(dado, "big", signed=False))  # 255
print(int.from_bytes(dado, "big", signed=True))   # -1
O byte é o mesmo; mudamos apenas a forma de interpretá-lo.

6 · Inteiros com sinal

Como representar números negativos sem adicionar um símbolo “−”?

Em memória não existe um caractere de menos colocado ao lado do número. Precisamos reservar padrões binários que representem valores negativos.

Sem sinal · n bits

0 até 2ⁿ − 1

Todos os padrões representam valores não negativos.

Com 8 bits: 0 a 255.

Complemento de dois · n bits

−2ⁿ⁻¹ até 2ⁿ⁻¹ − 1

Metade dos padrões representa valores negativos.

Com 8 bits: −128 a 127.

Negação em complemento de dois

Em uma largura fixa, uma forma operacional de obter o negativo é inverter os bits e somar 1.

Exemplo com 4 bits

O bit mais à esquerda

Em complemento de dois, valores negativos têm o bit mais significativo igual a 1 e os não negativos têm 0. Mas esse bit não funciona isoladamente como uma simples etiqueta de sinal: ele participa do valor da representação.

7 · Overflow

O resultado matemático pode existir e mesmo assim não caber

Quando trabalhamos com largura fixa, a faixa de valores também é fixa. Se o resultado ultrapassa essa faixa, a representação não consegue expressá-lo normalmente.

4 bits com sinalFaixa: −8 a +7.
Valor máximo0111 = +7
Somamos 10111 + 0001
Padrão obtido1000, que em complemento de dois de 4 bits representa −8.
Atenção: o comportamento observado em uma linguagem depende de seus tipos e regras. O hardware trabalha com larguras finitas, mas linguagens podem promover valores, detectar erros ou usar inteiros de precisão arbitrária. O Python, por exemplo, não limita seus inteiros comuns a 8, 16, 32 ou 64 bits.
def u8(valor):
    return valor & 0xFF

print(u8(255))      # 255
print(u8(255 + 1))  # 0


def s8(valor):
    valor &= 0xFF
    return valor - 256 if valor >= 128 else valor

print(s8(127))      # 127
print(s8(127 + 1))  # -128
O código simula uma largura fixa de 8 bits para tornar visível um limite que o inteiro padrão do Python normalmente esconde.

8 · Ponto flutuante

Nem todo número real pode ser representado exatamente

Inteiros de largura fixa têm um intervalo finito. Para representar números com parte fracionária e ordens de grandeza muito diferentes, computadores usam formatos de ponto flutuante.

Sinalpositivo ou negativo
Expoenteescala do número
Fração / significandodígitos significativos armazenados

A ideia

O formato é semelhante ao princípio da notação científica: uma quantidade limitada de bits representa sinal, escala e precisão. Como o conjunto de padrões possíveis é finito, apenas certos valores reais podem ser representados exatamente.

0.1 + 0.2
Em decimalEsperamos 0,3.
Em ponto flutuante binário0,1 e 0,2 não possuem uma representação binária finita exata nesse formato usual, então são armazenados como aproximações.
ConsequênciaA operação também trabalha sobre essas aproximações.
print(0.1 + 0.2)
print(format(0.1, ".20f"))
print(format(0.2, ".20f"))
print(format(0.3, ".20f"))

Precisão limitada

Ponto flutuante não representa “todos os reais”. Ele representa um conjunto finito de padrões distribuídos ao longo de uma grande faixa de magnitudes.

Implicação para software

Comparações exatas entre resultados de cálculos de ponto flutuante podem ser inadequadas em alguns casos. O desenvolvedor precisa conhecer as propriedades da representação usada.

Não aprofundaremos hoje: organização bit a bit dos formatos IEEE 754, números subnormais, NaN, infinitos, arredondamento e underflow. O objetivo é reconhecer por que a aproximação existe.
