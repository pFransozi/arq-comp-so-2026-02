Transição da Arquitetura para Sistemas Operacionais

Já estudamos os recursos. Agora precisamos coordená-los.

CPU, memória, armazenamento e dispositivos de entrada e saída não funcionam de maneira isolada. Durante a execução de software, vários programas podem precisar desses recursos ao mesmo tempo.

1 · CPUSe vários programas querem executar, quem decide qual deles usa o processador?
2 · MemóriaQuem define quais regiões de memória cada programa pode utilizar?
3 · ArmazenamentoComo diferentes programas conseguem acessar arquivos sem controlar diretamente o dispositivo?
4 · DispositivosQuem coordena teclado, tela, rede, USB e outros periféricos?

Ponte para esta aula: a primeira metade da disciplina observou a máquina e seus recursos. A partir daqui, estudaremos como esses recursos são apresentados, compartilhados e protegidos para que os programas possam utilizá-los.

1 · O problema

Um computador moderno executa muitos programas sobre poucos recursos físicos

Imagine um computador executando navegador, editor de código, aplicativo de videoconferência, sincronização de arquivos e atualização do sistema. Todos dependem dos mesmos processadores, da mesma memória e dos mesmos dispositivos.

Aplicações
Navegador · IDE · player · banco de dados · utilitários
Sistema Operacional
coordenação · abstração · proteção
Hardware
CPU · RAM · armazenamento · rede · dispositivos
Imagine sem o SOproblema conceitual

Cada aplicação teria de conhecer o hardware

Um programa que precisasse gravar dados teria de conhecer controladores, endereços, protocolos do dispositivo, interrupções e detalhes de transferência.

Cada aplicação teria de disputar recursos diretamente

Também seria necessário decidir quem usa CPU, memória, disco e dispositivos quando vários programas solicitassem os mesmos recursos.

Primeira definição operacional: o sistema operacional é o software de base que cria uma interface utilizável sobre o hardware e coordena o uso dos recursos físicos pelos programas.

2 · Duas perspectivas complementares

O sistema operacional como máquina estendida e como gerenciador de recursos

Uma introdução clássica aos sistemas operacionais pode ser organizada a partir de duas funções. Elas não competem entre si: descrevem o mesmo sistema a partir de pontos de vista diferentes.

Fornecer abstrações

Visão de cima para baixo

O SO esconde muitos detalhes do hardware e oferece objetos e operações mais simples aos programas.

Exemplo

A aplicação trabalha com um arquivo, em vez de controlar diretamente setores, controladores e protocolos de armazenamento.

Gerenciar recursos

Visão de baixo para cima

O SO controla e arbitra o uso de processador, memória, armazenamento e dispositivos entre programas concorrentes.

Exemplo

Se dez processos estão prontos para executar, algum mecanismo precisa decidir como o tempo de CPU será distribuído.

Aplicações ↓ usam abstrações e solicitam serviços Sistema Operacional ↓ controla e organiza CPU · memória · armazenamento · E/S

3 · Abstrações

O programa trabalha com conceitos mais simples que o hardware real

Abstrair não significa eliminar o hardware. Significa criar uma interface estável que permite ao programa utilizar o recurso sem conhecer todos os detalhes da implementação física.

Recurso físicoAbstração ou serviço observado pelo softwareO que é simplificado
CPUProcesso / threadExecução concorrente e compartilhamento do processador
Memória RAMEspaço de endereçamentoOrganização e isolamento da memória utilizada pelo programa
SSD / HDDArquivo e diretórioOrganização persistente dos dados sem acesso direto ao dispositivo
RedeInterfaces de comunicaçãoEnvio e recebimento sem que a aplicação controle diretamente o hardware de rede
PeriféricosDispositivos acessados por interfaces do SODiferenças de controladores e protocolos específicos

Exemplo: salvar um arquivo

Aplicação ↓ "grave estes dados neste arquivo" Sistema Operacional ↓ sistema de arquivos Driver / controlador ↓ Dispositivo de armazenamento

A aplicação expressa a operação em um nível de abstração útil ao software. O sistema operacional transforma essa solicitação em operações compatíveis com o sistema de arquivos e com o dispositivo.

4 · Gerenciamento de recursos

Compartilhar recursos exige decisões

Quando existem mais solicitações que recursos imediatamente disponíveis, o sistema operacional precisa controlar o compartilhamento.

CPU

Vários processos podem estar prontos ao mesmo tempo. O SO mantém informações sobre eles e decide qual poderá executar.

Memória

O SO controla quais regiões pertencem a cada processo, evita acessos indevidos e administra a memória disponível.

Arquivos e armazenamento

O SO organiza nomes, diretórios, permissões, leitura e escrita de dados persistentes.

Dispositivos de E/S

O SO coordena operações com teclado, tela, USB, rede e outros dispositivos, normalmente por meio de drivers.

Compartilhamento no tempo e no espaçoideia inicial

No tempo

Um recurso é utilizado por diferentes programas em momentos diferentes. A CPU é o exemplo mais importante: os processos se alternam no uso dos núcleos disponíveis.

No espaço

Um recurso pode ser dividido. A memória principal, por exemplo, pode manter regiões utilizadas por diferentes processos ao mesmo tempo.

Importante: ainda não estamos estudando como o escalonador ou o gerenciador de memória implementam essas decisões. Nesta aula interessa compreender por que essas decisões existem.

5 · Proteção

Uma aplicação não deve poder controlar livremente toda a máquina

Se qualquer programa pudesse alterar qualquer endereço de memória, configurar dispositivos ou interromper outros programas, não haveria isolamento confiável entre aplicações.

Modo usuário
Aplicações executam com privilégios limitados
Modo núcleo
O kernel pode executar operações privilegiadas e controlar recursos
Hardware
O processador fornece mecanismos que sustentam essa separação

Modo usuário

Objetivo

Limitar o que um programa comum pode fazer diretamente. Isso reduz a possibilidade de uma aplicação comprometer todo o sistema.

Modo núcleo

Objetivo

Permitir ao kernel executar operações necessárias para controlar memória, processadores, interrupções e dispositivos.

Questão que fica para a próxima etapa: se a aplicação está em modo usuário, como ela pede ao kernel para abrir um arquivo, criar um processo ou acessar um dispositivo?

6 · Interface com o sistema operacional

Aplicações solicitam serviços ao kernel

Um programa precisa de uma forma controlada de atravessar a fronteira entre execução em modo usuário e serviços fornecidos pelo sistema operacional.

Aplicação ↓ solicita uma operação Interface do sistema ↓ Kernel ↓ realiza a operação de forma controlada Recurso físico ou estrutura do SO

Chamaremos essas operações de chamadas de sistema. Elas formam uma interface fundamental entre programas e kernel. Nesta aula basta reconhecer o papel dessa interface; o mecanismo será estudado em uma aula própria.

Necessidade da aplicaçãoServiço esperado do SO
Abrir e ler dados persistentesOperações sobre arquivos
Iniciar outro programaCriação e gerenciamento de processos
Solicitar mais memóriaGerenciamento do espaço de memória do processo
Enviar dados pela redeOperações de comunicação e E/S

Referência para o percurso da disciplina: o MIT 6.S081 organiza o estudo prático justamente a partir de uma introdução ao SO e, em seguida, avança para organização do sistema e chamadas de sistema, tabelas de páginas, traps, interrupções, escalonamento e sistemas de arquivos. Aqui usaremos essa abordagem como referência de engenharia, adaptada ao escopo do nosso componente.

7 · Diferentes contextos

Nem todo sistema operacional é projetado para o mesmo objetivo

Os princípios fundamentais permanecem, mas os requisitos mudam conforme o ambiente em que o sistema será utilizado.

ContextoExemplos de preocupação
Computadores pessoaisResponsividade, compatibilidade, interface com usuário e execução de muitos aplicativos
ServidoresConcorrência, disponibilidade, uso eficiente de CPU, memória, armazenamento e rede
Sistemas móveisEnergia, sensores, conectividade, isolamento de aplicações e recursos limitados
Sistemas embarcadosRecursos específicos, restrições de hardware, consumo e função dedicada
Sistemas de tempo realRespostas dentro de restrições temporais e comportamento previsível
RTOS neste semestre: sistemas operacionais de tempo real continuam sendo relevantes, mas serão tratados como uma categoria específica dentro do estudo de sistemas operacionais. A discussão sobre deadlines, latência e previsibilidade será retomada quando estudarmos processos e escalonamento.

Prática guiada · Autópsia de cenários

Identifique onde o sistema operacional precisa atuar

Esta atividade reaproveita a estrutura do material anterior, agora sem utilizar RTOS como eixo da primeira aula. Para cada cenário, analise os recursos envolvidos e a coordenação realizada pelo sistema operacional.

EtapaPergunta
1 · RecursosQuais recursos estão envolvidos: CPU, memória, armazenamento, rede ou dispositivos?
2 · CoordenaçãoO que o sistema operacional precisa gerenciar: execução, memória, arquivos, comunicação ou dispositivos?
3 · DisputaExiste mais de uma tarefa competindo pelo mesmo recurso?
4 · SintomaQual comportamento o usuário consegue observar: lentidão, fila, travamento, alto uso de CPU, uso intenso de disco ou outro efeito?
Exemploarquivo grande

Abrindo um PDF de 200 MB

Recursos: armazenamento, memória e CPU.

Coordenação: iniciar a aplicação, localizar e ler o arquivo, manter dados em memória e permitir a execução do leitor.

Sintoma possível

A abertura pode demorar enquanto leitura, alocação de memória e processamento acontecem. O fato de a aplicação parecer realizar uma única ação não significa que apenas um recurso esteja envolvido.

Cenário A · Copiar muitas fotos

Você copia 2.000 fotos de um celular para o notebook. A transferência demora, mas o computador continua utilizável.

  1. Qual recurso parece dominar o tempo da operação?
  2. Por que a CPU pode permanecer relativamente disponível?
  3. Quais dispositivos e estruturas de arquivos o SO precisa coordenar?
  4. Por que a interface continua responsiva mesmo com a cópia em andamento?

Cenário B · Vídeo durante atualização

Um vídeo está sendo reproduzido enquanto o sistema realiza uma atualização ou uma varredura de segurança. O vídeo começa a apresentar travamentos.

  1. Quais processos estão concorrendo?
  2. Quais recursos podem estar sendo disputados?
  3. Que papel o escalonamento da CPU pode ter nesse comportamento?
  4. Como operações de armazenamento podem contribuir para a lentidão?

Cenário C · Testes, IDE e navegador

Uma suíte de testes é executada repetidamente com IDE e navegador abertos. O código não muda, mas o tempo total varia entre as execuções.

  1. Por que o tempo pode variar mesmo com o mesmo código?
  2. Quais recursos estão sendo compartilhados?
  3. Como falta de memória disponível pode afetar o resultado?
  4. Por que medir o desempenho de um programa exige observar o estado do sistema?

O SO fornece aos programas interfaces mais simples que os mecanismos físicos do hardware.

O SO participa do isolamento entre aplicações e controla operações que exigem privilégios.
